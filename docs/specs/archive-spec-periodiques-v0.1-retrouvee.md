# Spec — Périodiques : l'autorité de titre et l'état de collection

**Version** : 0.1 — 27/08/2026
**Auteur·rices** : Xavier (arbitrages) + Claude (rédaction)
**Statut** : cadré, non implémenté
**Origine** : deux demandes d'adhésion — Anarchief.org (~100 titres de revues depuis les années 1860) et Bibliothèque SOLIDAIRES (12 titres, 91 fascicules déjà listés). Le réseau compte aujourd'hui 7 notices `periodico` sur 2 676.

**Dépendances** : `spec-granularite-item.md` (niveau exemplaire), `spec-conventions-catalographiques v0.1` (Atelier autorités), `spec-refactor-v3-semantique.md` (doctrine RPC).

---

## 1. Le problème, énoncé exactement

AnarBib possède déjà **des champs de périodique** sur `public.books` :

```
issn · titulo_periodico · volume · numero · fasciculo · data_edicao · periodicidade
artigo_source · artigo_volume · artigo_issue · artigo_pages
```

Ce qui manque n'est pas un champ, c'est **un objet**. Le titre d'une revue est aujourd'hui une chaîne de caractères recopiée sur chaque fascicule (`titulo_periodico`, texte libre, rempli sur 2 notices sur 7). Il n'est ni une entité, ni une autorité, ni une cible de lien.

Quatre conséquences, toutes vérifiées en base :

**1.1 — Aucun regroupement fiable.** « Tous les numéros du *Libertaire* » suppose que la chaîne ait été tapée à l'identique partout. Elle ne le sera pas, sur 100 titres et deux langues.

**1.2 — Aucun état de collection.** Impossible d'écrire « nous avons 1896-1914, sauf le n°23 et 1902 ». C'est pourtant l'information qui décide d'une demande de prêt entre bibliothèques : sans elle, on demande à l'aveugle, ou on ne demande pas.

**1.3 — La détection de doublons produit des faux positifs.** `suggest_catalog_duplicates` rapproche les notices par similarité trigramme sur `titulo`. Quatre notices *Encontros com a Civilização brasileira* existent déjà, titre strictement identique, sans numéro, ne différant que par l'année : la fonction les voit comme des doublons. Avec 91 fascicules Solidaires et une centaine de titres Anarchief, la file de l'Atelier se remplira de paires légitimes à écarter une par une.

**1.4 — Le changement de titre est ingérable.** Un journal de 1890 qui change de nom en 1905, saisi sous deux chaînes différentes, produit deux collections sans lien. Sur un fonds qui court de 1860 à aujourd'hui, ce n'est pas un cas d'école : c'est la règle.

## 2. Principes retenus

**P1 — Le titre de périodique devient une autorité de plein exercice**, de la même famille que `authors`, `subjects` et `publishers`. Il en reprend la forme : slug, statut, libellés i18n, formes rejetées, notes d'application, et passage par l'Atelier autorités pour la création, la correction et la fusion.

**P2 — Le fascicule reste une notice `books`.** On n'invente pas une table de fascicules. Un numéro de revue est un document catalogué, prêtable, numérisable, réservable, exactement comme un livre — il hérite donc de toute la machinerie existante (exemplaires, holdings, PEB, partage numérique, ressources numériques). Il gagne seulement un lien vers son titre.

**P3 — Rien n'est détruit.** `titulo_periodico` est conservé tel quel : il devient la **forme transcrite** (ce qui est imprimé sur le fascicule), à côté de la forme d'autorité. C'est une distinction catalographique classique et elle sert : un fascicule peut porter un titre légèrement différent de la forme retenue.

**P4 — Le niveau article n'est pas ouvert maintenant.** Le vocabulaire l'anticipe (`tipo_material = 'artigo'`, `artigo_source/volume/issue/pages`), le modèle ci-dessous prévoit son point d'accroche, mais rien n'est implémenté tant qu'une bibliothèque n'en a pas l'usage réel. Voir §12.

**P5 — Pas de bulletinage.** L'enregistrement des numéros à réception, les abonnements, les circuits de circulation : hors périmètre. Nos bibliothèques sont des archives et des fonds militants, pas des abonnées institutionnelles. Si le besoin apparaît, il fera sa propre spec.

**P6 — L'état de collection est déclaré autant que calculé.** Le calcul depuis les fascicules présents ne dit jamais qu'une lacune est définitive. Une archive, si.

## 3. Modèle de données

### 3.1 `public.serials` — l'autorité de titre

Calquée sur `public.subjects` (slug, statut, i18n, notes) et enrichie de ce qu'un titre de périodique exige.

```sql
create table public.serials (
  id                bigint generated by default as identity primary key,

  -- identité
  slug              text not null unique,
  uniform_title     text not null,               -- forme retenue
  sort_title        text,                        -- forme de tri (article initial écarté)
  title_nonfiling   smallint not null default 0, -- caractères initiaux à ignorer au tri
  alt_i18n          jsonb  not null default '{}'::jsonb, -- formes parallèles/variantes par locale
  hidden_i18n       jsonb  not null default '{}'::jsonb, -- formes rejetées, pour la recherche

  -- identifiants
  issn              text,
  issn_l            text,                        -- ISSN de liaison (relie les supports)

  -- description
  publisher_id      bigint references public.publishers(id) on delete set null,
  emitter_org       text,                        -- organisation éditrice (souvent ≠ éditeur)
  place_publication text,
  country_code      text,
  language          text,                        -- langue principale, ISO 639-1
  periodicidade     text,                        -- vocabulaire libre, aligné sur books.periodicidade
  start_year        text,                        -- texte : « 1896 », « ca. 1902 »
  end_year          text,                        -- null = en cours
  is_continuing     boolean not null default true,
  scope_note        text,

  -- filiation (changements de titre)
  predecessor_id    bigint references public.serials(id) on delete set null,
  successor_id      bigint references public.serials(id) on delete set null,

  -- gouvernance, calquée sur subjects
  status            text not null default 'proposto',
  created_at        timestamptz not null default now(),
  created_by        uuid,
  updated_at        timestamptz not null default now(),
  updated_by        uuid,

  constraint serials_status_chk check (status in ('proposto','aprovado','obsoleto')),
  constraint serials_slug_not_blank check (btrim(slug) <> ''),
  constraint serials_title_not_blank check (btrim(uniform_title) <> ''),
  constraint serials_no_self_predecessor check (predecessor_id is distinct from id),
  constraint serials_no_self_successor   check (successor_id  is distinct from id)
);

create index serials_uniform_title_trgm on public.serials
  using gin (uniform_title extensions.gin_trgm_ops);
create index serials_issn_idx    on public.serials (issn) where issn is not null;
create index serials_status_idx  on public.serials (status);
```

> **Note sur `status`** : le vocabulaire reprend celui de `subjects` (défaut `proposto`). Une revue importée en masse arrive donc *proposée*, pas *approuvée* — c'est l'Atelier qui la promeut. Cohérent avec la doctrine : aucune autorité ne naît validée d'un import.

> **Note sur la filiation** : `predecessor_id`/`successor_id` sont deux liens simples plutôt qu'une table de relations. Une revue peut naître d'une fusion de deux titres — ce cas se traite en chaînant, avec la note d'application pour le dire en clair. Une table de relations n-n serait plus juste et beaucoup plus lourde à manipuler ; à rouvrir seulement si le fonds Anarchief l'impose (§13, TODO 2).

### 3.2 Lien fascicule → titre

```sql
alter table public.books

create index books_serial_id_idx on public.books (serial_id) where serial_id is not null;
```

`titulo_periodico` **reste** et change de rôle : forme transcrite. À documenter par un commentaire de colonne, sinon la distinction se perdra.

```sql
comment on column public.books.titulo_periodico is
  'Titre de périodique TEL QUE TRANSCRIT sur le fascicule. La forme d''autorité est portée par serials via books.serial_id. Les deux coexistent volontairement.';
comment on column public.books.serial_id is
  'Titre de périodique en forme d''autorité. NULL pour tout ce qui n''est pas un fascicule.';
```

### 3.3 Clé de désignation du fascicule

Le tri « n°1, n°2, n°10 » ne se fait pas alphabétiquement, et l'égalité de deux fascicules ne se juge pas sur le titre. On calcule une clé.

```sql
create or replace function public.fn_serial_issue_key(
  p_volume text, p_numero text, p_fasciculo text, p_data_edicao text, p_ano text)
returns text
language sql immutable
as $$
  select nullif(btrim(concat_ws('|',
    nullif(regexp_replace(coalesce(p_volume,''),    '\D', '', 'g'), ''),
    nullif(regexp_replace(coalesce(p_numero,''),    '\D', '', 'g'), ''),
    nullif(regexp_replace(coalesce(p_fasciculo,''), '\D', '', 'g'), ''),
    nullif(btrim(lower(coalesce(p_data_edicao,''))), ''),
    nullif(btrim(coalesce(p_ano,'')), '')
  )), '');
$$;
```

Stockée en colonne générée, pour être indexable et lisible en relecture :

```sql
alter table public.books
  add column issue_key text generated always as (
    public.fn_serial_issue_key(volume, numero, fasciculo, data_edicao, ano)
  ) stored;

create index books_serial_issue_idx on public.books (serial_id, issue_key)
  where serial_id is not null;
```

> **Pourquoi pas un tri numérique pur** : les fascicules militants portent des désignations impossibles à normaliser (« n° spécial », « été 1936 », « 12/13 »). La clé mélange donc chiffres et date, et sert à **distinguer**, pas à ordonner parfaitement. L'ordre d'affichage se fait sur `(ano, issue_key)` avec repli sur le titre.

### 3.4 État de collection

```sql
create table public.serial_holdings (
  id             bigint generated by default as identity primary key,
  serial_id      bigint not null references public.serials(id) on delete cascade,
  library_id     uuid   not null references public.libraries(id) on delete cascade,

  -- déclaré par la bibliothèque, fait foi
  statement      text,               -- « 1896-1914, lacunes : n°23, 1902 »
  gaps_note      text,
  completeness   text not null default 'desconhecida',
  is_public      boolean not null default true,

  -- calculé depuis les fascicules effectivement catalogués
  computed_first text,
  computed_last  text,
  computed_count integer not null default 0,
  computed_at    timestamptz,

  created_at     timestamptz not null default now(),
  updated_at     timestamptz not null default now(),
  updated_by     uuid,

  constraint serial_holdings_unique unique (serial_id, library_id),
  constraint serial_holdings_completeness_chk
    check (completeness in ('completa','quase_completa','parcial','esparsa','desconhecida'))
);
```

**Doctrine du champ `statement`** : quand il est rempli, il est ce qui s'affiche. Le calcul ne le remplace jamais — il l'accompagne, et une divergence entre les deux est une information utile, pas une erreur à corriger automatiquement.

Fonction de recalcul, à appeler après import ou catalogage :

```sql
create or replace function public.fn_recompute_serial_holdings(
  p_serial_id bigint, p_library_id uuid)
returns void
language sql security definer
set search_path to 'public','pg_catalog'
as $$
  insert into public.serial_holdings (serial_id, library_id, computed_first, computed_last,
                                      computed_count, computed_at)
  select p_serial_id, p_library_id,
         min(b.ano), max(b.ano), count(*), now()
  from public.books b
  join public.book_holdings h on h.book_id = b.id
  where b.serial_id = p_serial_id and h.library_id = p_library_id
  on conflict (serial_id, library_id) do update
    set computed_first = excluded.computed_first,
        computed_last  = excluded.computed_last,
        computed_count = excluded.computed_count,
        computed_at    = excluded.computed_at;
$$;
```

## 4. La règle anti-faux-doublons

C'est le point qui rend le reste utilisable, et il se greffe sur un mécanisme déjà présent.

`suggest_catalog_duplicates` écarte déjà les paires partageant une même œuvre :

```sql
and not (r.work_a is not null and r.work_b = r.work_a)
```

On ajoute la règle symétrique pour les périodiques. Dans la CTE `brut`, remonter `a.serial_id`, `b.serial_id`, `a.issue_key`, `b.issue_key` ; puis dans `retenues`, ajouter :

```sql
-- Deux fascicules d'un même périodique ne sont pas des doublons dès lors que
-- leur désignation diffère. S'ils portent la MÊME désignation, la détection
-- reste active : c'est alors un vrai doublon de saisie.
and not (
      r.serial_a is not null
  and r.serial_b = r.serial_a
  and r.issue_a is not null and r.issue_b is not null
  and r.issue_a <> r.issue_b
)
```

> **Pourquoi pas exclure toute paire de même `serial_id`** : parce que le doublon de saisie du même numéro est fréquent — c'est même le doublon le plus probable sur un import de 91 fascicules. On écarte le bruit, pas le signal.

**Cas résiduel connu** : deux fascicules d'un même titre sans aucune désignation (`issue_key` nul des deux côtés) restent détectés comme doublons. C'est voulu : deux notices d'une même revue sans numéro ni date *sont* un problème de catalogage, qu'il faut voir.

**Effet immédiat sur l'existant** : les quatre *Encontros com a Civilização brasileira* portent tous `ano` (1978, 1978, 1979, 1979) mais aucun numéro. Après rattachement à un `serial_id` commun, deux paires sortiront de la détection (années différentes) et deux y resteront (années identiques) — ce qui est exactement le bon résultat : ces deux-là méritent un œil.

## 5. Atelier autorités

Le titre de périodique entre dans la machinerie existante plutôt que d'en avoir une nouvelle.

- `authority_proposals.target_kind` : élargir le CHECK à `'serial'` (aujourd'hui `author` / `subject`).
- **Fusion** : `merge_serial(p_canonical_id, p_duplicate_id)` sur le modèle de `merge_subject` — repointe `books.serial_id`, fusionne `serial_holdings` par bibliothèque, reporte `alt_i18n`/`hidden_i18n`, journalise dans `merge_log`, supprime le doublon.
- **Non-doublons** : table `serial_not_duplicate` symétrique de `author_not_duplicate`, avec `mark_serials_not_duplicate` / `unmark_serials_not_duplicate`.
- **Détection d'autorités** : `suggest_authority_duplicates` doit couvrir les titres de revues — deux `serials` de titre proche **sont** de vrais doublons candidats, contrairement à leurs fascicules.
- **Alignement FICEDL** : hors périmètre. Le thésaurus FICEDL indexe des matières, pas des titres. Ne pas forcer l'analogie.

## 8. Reprise de l'existant

Sept notices, dont quatre déjà problématiques. Reprise manuelle assistée, pas automatique.

1. Créer les titres depuis les `titulo_periodico` distincts non nuls : *Puxirum*, *Ação Direta*.
2. Les trois notices sans `titulo_periodico` (*Verve*, et les quatre *Encontros…*) : le titre du fascicule **est** le titre de la revue. Créer les deux titres, rattacher, puis renseigner `ano` en désignation.
3. Recalculer les états de collection.
4. Vérifier que les paires *Encontros* se comportent comme prévu en §4.

Requête de départ :

```sql
select id, titulo, titulo_periodico, numero, ano, tipo_material
from public.books
where tipo_material = 'periodico' or titulo_periodico is not null
order by coalesce(titulo_periodico, titulo), ano;
```

## 9. Gardes et pièges

**G1 — Cycle de filiation.** `fn_serial_set_filiation` doit refuser un cycle (A précède B qui précède A). Parcours récursif borné à 20 sauts, exception au-delà.

**G2 — Réciprocité de la filiation.** Poser `A.successor_id = B` ne pose pas `B.predecessor_id = A`. Soit un trigger de symétrie (modèle `partnership_rights`), soit la discipline dans la RPC. **Trigger recommandé** : la discipline ne survit pas à six mois.

**G3 — `serial_id` sur un non-fascicule.** Rien n'empêche techniquement de poser `serial_id` sur un livre. Trigger de garde : `serial_id` non nul ⇒ `tipo_material in ('periodico','artigo')`.

**G4 — Colonne générée et import.** `issue_key` est `GENERATED ALWAYS` : tout `insert` qui tenterait de l'écrire échouera. Le pipeline d'import ne la mentionne pas — vérifier que `process-partner-catalog-import` ne fait pas de `select *` suivi d'un `insert` symétrique.

**G5 — Fusion et états de collection.** `merge_serial` doit fusionner les `serial_holdings` par bibliothèque, pas les écraser : deux titres fusionnés peuvent chacun porter un `statement` rédigé à la main. Concaténer avec une marque, et laisser la coordination trancher.

**G6 — Ordre d'affichage.** Trier sur `issue_key` seul donnerait « 1, 10, 2 » pour les désignations non numériques. Toujours `order by ano nulls last, issue_key nulls last, titulo`.

## 12. Hors périmètre, explicitement

- **Bulletinage, abonnements, circuits de circulation** (P5 du §2).
- **Niveau article.** Point d'accroche prévu : une notice `tipo_material='artigo'` porterait `serial_id` (la revue) plus un lien vers le fascicule — colonne `parent_book_id` à créer le jour venu. Ne rien poser maintenant.
- **Alignement FICEDL des titres** (§5).
- **Indexation matière au niveau du fascicule** : elle existe déjà via `book_subjects`, rien de spécifique.

## 13. TODO à arbitrer

1. **Vocabulaire de `periodicidade`** : libre ou liste fermée ? Aujourd'hui libre et vide. Une liste fermée aiderait l'affichage ; elle demande un travail de vocabulaire multilingue. *Penchant : libre en P1, liste en P9.*

4. **Promotion automatique** : un titre `proposto` rattaché à plus de N fascicules dans plus de M bibliothèques doit-il être promu automatiquement ? *Penchant : non. La promotion est un geste, pas un seuil.*
5. **Affichage OPAC** : la revue est-elle une page à part entière (`/periodico/<slug>`) ou une facette du catalogue ? *Penchant : page à part entière — c'est ce qui rend l'état de collection lisible.*

## 14. Vérifications de clôture

- [ ] Un fascicule créé sans `serial_id` reste catalogable — la spec n'impose rien de nouveau au monographies.
- [ ] Deux fascicules de numéros différents d'une même revue **n'apparaissent plus** dans `suggest_catalog_duplicates`.
- [ ] Deux fascicules de même désignation y apparaissent **toujours**.
- [ ] Un titre `proposto` est invisible au public, visible du staff.
- [ ] `merge_serial` repointe les fascicules, fusionne les états de collection, écrit dans `merge_log`.
- [ ] La filiation refuse un cycle et pose bien les deux côtés.
- [ ] `serial_id` refuse un `tipo_material` inadapté.
- [ ] L'import du CSV Solidaires crée 12 titres et rattache 91 fascicules, sans toucher aux 1 582 monographies.
- [ ] Les dix locales ont les libellés — pas de repli silencieux.
