## 6. Workflow réservation — Phase 2 paquet B (2 wrappers sensibles)

### `api.confirm_pickup_v1(p_reserva_id, p_line_no, p_loan_options jsonb)` returns **bigint** (loan_id)

- Strict : `current_stage = 'pronta_para_retirada'` (pas la matrice générique)
- Conversion atomique réserve→emprunt via `fn_v2_convert_reserva_linhas_to_emprestimo`
- Vérifications cotisation déléguées à la fn_v2_* (qui appelle `fn_is_loan_blocked_by_dues`)
- Calcul `due_at` automatique via `api.resolve_circulation_rule` si absent dans `p_loan_options`

### `api.cancel_reservation_as_library(p_reserva_id, p_line_no, p_reason)` returns integer

- **Exclusif coordenador** (refus explicite des librarians avec `coordenador_required`)
- **Raison conditionnelle** : obligatoire ≥ 5 chars si `current_stage` ∈ `retirada_agendada` / `re-retirada_agendada` / `retirada_a_combinar` / `pronta_para_retirada`. Optionnelle pour `solicitada` / `em_preparacao`.
- Validation matrice via helper
- Le trigger `trg_auto_liberate_after_no_show` déclenche ensuite la bascule auto vers `liberada_para_circulacao` avec `final_reason = 'cancelled_by_library'`

### 7 tests de rejet passés

T_B_1..7 : auth, stages non-pronta, reservas inexistantes, RLS protectrice, transitions terminales, inspection statique de la logique conditionnelle.

### Tests non exécutés en runtime (besoin de données dans stages intermédiaires)

- Cancel par librarian → `coordenador_required`
- Cancel sans raison sur stage avancé → `reason_required_min_5_chars`
- Conversion réussie réserve→emprunt + déclenchement trigger
- Cancel réussi en `cancelada_biblioteca` + cascade auto vers `liberada_para_circulacao`

Ces 4 chemins seront naturellement exercés en phase 5+6 (frontend) quand de vrais workflows ouvriront des lignes dans ces stages.
